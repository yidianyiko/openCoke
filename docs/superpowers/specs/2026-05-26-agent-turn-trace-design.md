# Agent Turn Trace Design

## Why

Coke's Agent Runtime already separates execution from domain ownership:
Reminder, Memo, Calendar Import, Timezone, Channel, Bridge, and Gateway own
their product contracts, while Agent Runtime owns turn processing, locks,
capability invocation, output handling, and runtime guardrails.

That boundary is necessary but not enough for iteration. When a turn fails or
behaves poorly, the repository should answer:

- which route the runtime chose
- which agent and tools ran
- which domain or capability results existed
- whether guardrails changed the output
- whether the final reply came from the model, a domain summary, fallback, or
  no output
- where timeout, rollback, exception, or output failure happened

Ordinary logs are not the right source of truth for those answers. Logs are an
operational timeline. Agent turn trace is structured diagnostic evidence.

The design follows the practical lesson from Anthropic's "Building effective
agents": keep the runtime simple and composable, make tool interaction
transparent, and collect enough environment feedback to evaluate and improve
the system without adding autonomous complexity.

## Goal

Introduce an independent `AgentTurnTrace` evidence surface for every Agent
Runtime turn.

The first version should:

- be generated by default
- be separate from ordinary logs
- attach to `AgentRunResult.trace`
- optionally write JSONL evidence files
- support local full-content debugging
- keep server traces metadata-only by default
- never enter model context, chat history, Agno session history, output message
  metadata, or user-visible output

## Non-Goals

- Do not add an admin UI for traces in this slice.
- Do not add a production database trace table in this slice.
- Do not use traces as conversation memory.
- Do not make trace persistence part of the user-visible success path.
- Do not replace domain results, capability results, eval outputs, or ordinary
  logs.
- Do not introduce a new autonomous agent or orchestration layer.

## Core Principle

Agent turn trace is a private diagnostic sidecar.

It is not:

- a log substitute
- a user-content archive
- a prompt input
- a model memory source
- an output message field

Logs may carry `trace_id`, route, status, error code, and duration. The
structured trace record is the source of diagnostic evidence.

## Environment Profiles

Tracing is on by default, but the content level depends on runtime profile.

### Local, Dev, And Eval

Local and eval runs default to full trace:

```text
COKE_AGENT_TURN_TRACE_PROFILE=local
COKE_AGENT_TURN_TRACE_ENABLED=1
COKE_AGENT_TURN_TRACE_CONTENT=full
```

Full trace may include user input text, assistant output text, tool arguments,
tool result content, and domain facts when the run is local or explicitly
marked as eval evidence.

Full trace still must not enter:

- prompt text
- Agno session history
- chat history
- retrieval storage
- output message content
- output message metadata
- user-visible responses

### GCP Coke Server

The GCP Coke server defaults to metadata-only trace:

```text
COKE_AGENT_TURN_TRACE_PROFILE=server
COKE_AGENT_TURN_TRACE_ENABLED=1
COKE_AGENT_TURN_TRACE_CONTENT=metadata
```

Metadata-only trace records enum values, counts, ids or hashed ids, durations,
tool names, result indexes, output disposition, guardrail decisions, and error
codes. It does not record raw user text, raw assistant text, prompts, history,
tool payloads, or full domain facts.

Server profile must not silently switch to full content. A future emergency
override may be added only with a separate explicit flag and a retention rule.

## Runtime Data Shape

Use frozen dataclasses, matching the existing runtime result contracts.

`AgentRunResult.trace` should become `AgentTurnTrace`; do not add a second
parallel field such as `turn_trace`.

```python
@dataclass(frozen=True)
class AgentTurnTrace:
    schema_version: Literal["agent_turn_trace.v1"]
    trace_id: str
    turn: TraceTurn
    runtime: TraceRuntime
    routing: TraceRouting
    agent_calls: Sequence[TraceAgentCall]
    result_refs: Sequence[TraceResultRef]
    guardrails: Sequence[TraceGuardrail]
    output: TraceOutput
    error: TraceError | None
    redaction: TraceRedaction
```

### `TraceTurn`

Turn identity and source context:

```python
@dataclass(frozen=True)
class TraceTurn:
    input_type: Literal["user.turn", "reminder.fired"]
    message_source: str
    conversation_id: str
    owner_user_id: str
    character_id: str
    platform: str
    route_key: str | None
    occurred_at: datetime
    current_message_ids: Sequence[str]
    input_text_sha256: str | None
    input_text_chars: int
    reminder_id: str | None = None
    fire_id: str | None = None
```

Server metadata traces may hash ids before export. In-process traces may keep
internal ids when they do not cross into user-visible state.

### `TraceRuntime`

Runtime status and timing:

```python
@dataclass(frozen=True)
class TraceRuntime:
    name: Literal["agent_runtime"]
    status: str
    started_at: datetime
    finished_at: datetime | None
    duration_ms: int | None
    timeout_seconds: float | None
    failure_stage: str | None
```

`status` values include `ok`, `empty_output`, `rollback`, `timeout`,
`exception`, `unknown_tool`, and `output_failed`.

### `TraceRouting`

Runtime route decisions:

```python
@dataclass(frozen=True)
class TraceRouting:
    route: Literal[
        "direct_reply",
        "reminder_domain",
        "scheduling_domain",
        "utility_capability",
        "reminder_fired",
        "fallback",
        "unknown",
    ]
    reason: str
    preselected_intent: str | None
    forced_args_present: bool
```

`reason` must be a stable code, not a free-form model explanation. Examples:
`explicit_reminder_request`, `preselected_scheduling_intent`,
`product_notification_decision`, `reminder_fired_event`, `no_tool_requested`,
and `runtime_fallback`.

### `TraceAgentCall`

Agent calls and tool availability:

```python
@dataclass(frozen=True)
class TraceAgentCall:
    agent_id: str
    role: str
    status: str
    model_role: str
    max_tokens: int | None
    tool_names: Sequence[str]
    selected_tool_names: Sequence[str]
    started_at: datetime | None
    duration_ms: int | None
    error_code: str | None
```

This records prompts and tool interfaces by name only. It must not store prompt
text, model scratchpad, Agno `run_output.messages`, or raw tool payloads.

### `TraceResultRef`

Pointers to existing runtime result facts:

```python
@dataclass(frozen=True)
class TraceResultRef:
    kind: Literal["domain", "capability"]
    index: int
    name: str
    outcome: str
    operation_count: int
    effect_summary: Sequence[str]
    durable_write: bool | None
    error_code: str | None
```

`TraceResultRef` summarizes. It must not duplicate full
`DomainExecutionResult.operations[*].facts`, capability `content`,
`synthesis_context`, URLs, tokens, or user-authored content.

### `TraceGuardrail`

Runtime safety checks:

```python
@dataclass(frozen=True)
class TraceGuardrail:
    name: Literal[
        "durable_write_summary",
        "unconfirmed_durable_write_promise",
        "visible_identifier_leak",
    ]
    status: Literal["passed", "failed", "skipped"]
    error_code: str | None
```

Guardrail traces explain why visible output was accepted or suppressed.

### `TraceOutput`

Final output path:

```python
@dataclass(frozen=True)
class TraceOutput:
    disposition_status: str
    output_source: Literal[
        "model",
        "capability_summary",
        "domain_summary",
        "fallback",
        "empty",
    ]
    visible_message_count: int
    output_reference_count: int
    post_analyze_requested: bool
    fallback_reason: str | None
```

Full local trace may include content-bearing output evidence in the JSONL sink,
but `TraceOutput` itself stays structural.

### `TraceError`

Terminal error summary:

```python
@dataclass(frozen=True)
class TraceError:
    code: str
    retryable: bool
    stage: str
```

Do not record traceback text, raw exception strings, provider payloads, or
prompt snippets.

### `TraceRedaction`

Applied privacy policy:

```python
@dataclass(frozen=True)
class TraceRedaction:
    content_level: Literal["metadata", "full"]
    profile: Literal["local", "server", "eval"]
    policy: Literal["allowlist"]
    hashed_ids: bool
    text_fields_present: bool
```

The trace builder must be allowlist-first. If a field is not explicitly
allowed by this spec, it is not written.

The same `TraceRedaction` policy applies to every serialization path:
in-memory debug dumps, JSONL evidence, eval summaries, and safe log summaries
must all derive from the configured content level. Metadata mode must not gain
raw text or payload fields just because the writer is local to the process.

## JSONL Evidence Sink

Trace records may be written to JSONL:

```text
artifacts/evidence/agent-turn-traces/<suite>/<safe_run_id>.jsonl
```

Examples:

```text
artifacts/evidence/agent-turn-traces/dev/local-2026-05-26.jsonl
artifacts/evidence/agent-turn-traces/reminder-normal/reminder-normal-abc123.jsonl
artifacts/evidence/agent-turn-traces/shared-reminder-agent-smoke/coach-booking-abc123.jsonl
```

One line is one completed or failed turn:

```json
{
  "schema_version": "agent_turn_trace.v1",
  "record_type": "agent_turn_trace",
  "recorded_at": "2026-05-26T03:12:44.123Z",
  "trace_run_id": "local-2026-05-26",
  "record_id": "turn-uuid",
  "source": {
    "suite": "dev",
    "profile": "local",
    "runtime": "agent_runtime",
    "worker_tag": "[W0]",
    "pid": 12345
  },
  "trace": {}
}
```

`trace` is the serialized `AgentTurnTrace`.

Eval summary JSON files should not duplicate every trace record. They should
include a pointer:

```json
{
  "trace": {
    "enabled": true,
    "schema_version": "agent_turn_trace.v1",
    "path": "artifacts/evidence/agent-turn-traces/reminder-normal/<run>.jsonl",
    "record_count": 20,
    "content_level": "full"
  }
}
```

## Logging Contract

Ordinary logs should only contain a small safe summary:

```text
trace_id=<id> route=<route> status=<status> error_code=<code> duration_ms=<n>
```

Logs should not become the trace source of truth. Grep-based extraction is
only a rescue path for old runs, not the new design.

## Persistence Failure

Trace persistence must fail open for the user path.

If writing a trace fails:

- do not fail the turn
- do not change visible output
- do not retry indefinitely
- log a safe summary with `status=trace_emit_failed`
- keep the in-memory `AgentRunResult.trace` intact

The trace sink must never dump raw context as a fallback.

## Privacy And Retention

Metadata traces on server follow `ephemeral_runtime_retention` unless a future
production trace store defines a different policy.

Full traces are local or eval evidence. They may contain user text and must be
treated as sensitive evidence:

- write under `artifacts/evidence/agent-turn-traces/`
- use local filesystem permissions as narrowly as practical
- do not commit generated trace files unless they are synthetic and explicitly
  sanitized
- do not send full traces to provider logs, output metadata, or chat history

## Test Requirements

The implementation plan should include tests proving:

- `AgentRunResult.trace` is an `AgentTurnTrace`
- metadata profile does not contain raw input text, raw output text, prompt
  text, recent history, tool content, domain facts, or tracebacks
- local full profile can include content-bearing fields only in the JSONL
  record, not in prompt/session/history/output metadata
- trace persistence failure does not fail the user turn
- ordinary logs contain only the safe trace summary
- eval summary JSON points to the JSONL trace file instead of duplicating all
  trace records

## Verification Surface

This design touches `worker-runtime` and `repo-os` when implemented.

For this design document alone, docs verification is sufficient. The
implementation plan should route verification through diff-aware tooling before
choosing focused runtime tests.
